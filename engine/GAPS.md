# Known engine divergences and spike gaps

This file records differences between `pobcalc` and desktop Path of Building.
It is intentionally explicit: an unverified result must not be promoted as
parity.

## Open

- **Preset application is not implemented.** The CLI validates the three
  doctrine-approved preset names, but currently evaluates the configuration
  embedded in the build XML. Seed expectations must record that configuration.
- **Linux runtime is not hermetic.** Upstream vendors Windows LuaJIT and native
  modules. The wrapper currently requires a host LuaJIT plus a compatible
  `lua-utf8` module. Packaging those dependencies is required before release.
- **No desktop-verified seed oracle has been supplied.** Upstream PoB test
  builds are useful smoke inputs, but outputs generated by the same headless
  calculator are not independent evidence of desktop parity. Five expectations
  must be captured by a human from the pinned desktop PoB revision.
- **Warm-server mode is not implemented.** Each CLI call initializes PoB.
  A persistent JSON-RPC worker is required to measure the intended warm diff,
  rather than process startup.
- **Breakdown references are placeholders.** They identify a calculation slot
  but are not yet backed by persisted Tier-2 breakdown data.

## Closed

- The adapter calls upstream `calcs.getMiscCalculator`; it does not copy or
  modify PoB calculation logic.
- JSON field order and number formatting are fixed, so successful identical
  invocations are byte deterministic.
