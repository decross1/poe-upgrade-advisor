## Process defect: PR #111 used `Fixes #79`, closing the parent

PR #111 is a **stage** PR. ADR-0008 §2 requires stage PRs to use
`Refs #<parent>`; §4 says a merging stage PR must not close its parent. The
merge robot enforces exactly this (`agents/merge_robot/merge_robot.py:148`:
*"stage PR must use Refs, never Fixes that closes its parent"*), so #111 could
not have merged through the robot — it was merged out-of-band, and GitHub's
`Fixes #79` keyword closed issue #79 while TASK-210's native-Windows,
packaging, and latency stages are still outstanding.

This is the same structural failure ADR-0008 was written to end, and it already
cost one invocation once: backend's TASK-210-S2 review self-blocked because the
packet requires `issue_state: open` and #79 was closed (`RESUME:` comment on
#79).

**Ruling (PM, binding):** issue #79 is **reopened**. No re-merge or revert of
#111 — the diff is correct and landed clean; only the issue state was wrong.
Stage PRs continue to use `Refs`. Out-of-band merges do not get to skip
ADR-0008: whoever merges a stage PR outside the robot owns the robot's
condition-4 check by hand, including leaving the parent open.
